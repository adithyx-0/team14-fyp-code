01

What was proposed

From Abstract_Team14.docx and Team14_System_Design_Review.md — the committed objectives and architecture, not a re-derivation of them.

Political memes in Malayalam and Tamil are a major vehicle for opinion-shaping, but automated stance understanding (support / oppose / neutral) is almost unstudied for these languages. The one directly relevant paper, SYNAPSE (ACL 2026), uses a single model and offers no explainability or cross-lingual analysis. The project's stated goal is the first systematic multi-model comparison — classical, prompted VLM, and fine-tuned VLM — for Dravidian-language meme stance classification, with explainability and cross-lingual transfer layered on top.

Three parallel arms (the architectural core)

ArmApproachModels
Arm 1 — Classical baselineFrozen vision + text encoders, residual fusion head, 5-fold CV. The anchor every other arm is measured against.Swin-Tiny + MuRIL (BERT)
Arm 2 — VLM benchmarkingZero-shot, few-shot, chain-of-thought prompting, both label levelsGemini 2.5 Flash, PaliGemma-3B, Qwen2.5-VL-7B, LLaVA-1.6-7B
Arm 3 — PEFT fine-tuningLoRA/QLoRA (4-bit) on open-weight VLMs; ablation on rank, adapter layer count, seed. Gemini gets a parallel prompt-optimisation track instead (API-only, can't be fine-tuned).PaliGemma-3B, Qwen2.5-VL-7B, LLaVA-1.6-7B

Plus four shared layers

  • Explainability — Grad-CAM heatmaps + natural-language rationale generation, with an explicit faithfulness check between the two, as one shared module all arms call into.
  • Cross-lingual transfer — Malayalam ↔ Tamil, on the secondary (misogyny) dataset only, since the primary political-meme dataset has no Tamil half. Two distinct sub-flows: checkpoint transfer (Arms 1/3) and prompt-language transfer (Arm 2).
  • Evaluation — macro-F1 at both label levels, benchmarked against SYNAPSE (0.4256) and the Hateful Memes reference point.
  • Demo app — Gradio/Streamlit; accepts a meme image + optional caption; model choice is a visible dropdown, not an automatic "best" pick.

Datasets as scoped

DatasetRoleSize
Malayalam political memesPrimary — feeds Arms 1–3500 train / 100 test, 2-level labels (20:1 imbalance)
Tamil + Malayalam misogyny memesSecondary — cross-lingual transfer onlyNot yet acquired

System design (Candidate B — parallel arms, chosen over a sequential pipeline and a layered-service design) is already worked out in detail: HLD, LLD module table, a 5-risk self-critique with fixes, and diagrams already exist in the project folder (System design v5.jpg, Overall_Architecture_Elaborated.png, refined_system_architecture_hld.svg). That part of the rubric is largely in hand — see §4.

Arm 1 — Classical baselineDone
Frozen Swin-Tiny + frozen MuRIL, residual fusion head, class-weighted loss. OCR text (Tesseract) used as the text-branch input, since the source data has no caption field. 5-fold CV run, plus a final train-on-all/eval-on-held-out-100 run — the number that's actually comparable to SYNAPSE.

How this reads Arm 1's classical baseline (0.3940 Level-2) lands between our own SYNAPSE replication (0.3183) and the paper's fine-tuned-VLM number (0.4256) — a legitimate, defensible anchor result, not a discardable one. It is a genuinely comparable data point because it's evaluated on the same held-out 100-row test set SYNAPSE's own numbers come from.

Caveats already on record — state these up front, don't let the viva surface them first

  • Only 8 epochs, no learning-rate schedule or hyperparameter search — a first working run, not a tuned one. Likely has headroom.
  • OCR text has noise; roughly 20% of extractions are empty (no visible text, or Tesseract miss) and haven't been manually verified against ground truth.
  • Both backbones (Swin-Tiny, MuRIL) are fully frozen — only the fusion head is trained, per the spec. This is a designed constraint, not an oversight, but be ready to say so.

What to actually do in 3 days

The honest read: you have one solid, defensible result (Arm 1) and empty folders everywhere else. That is a normal place to be at Mid Review — the rubric doesn't require all nine units finished. Spend the 3 days where the marks actually are.

Where the marks are

Viva 10
Design 10
Lit. 5
Progress 10
Deck 5

"Project progress / implementation" is 10 of 40 marks — the same weight as system design alone, and less than viva + design combined (20). Three of the five criteria (viva, design, literature review — 25 marks) can be finished to a high standard from what already exists, with no GPU, no new dataset, and no risk of a broken demo mid-viva. Don't spend all three days chasing Arm 2/3 at the expense of these.

Must-do (cheap, no blocked dependencies, ~2 days of focused work)

  1. One real second data point for Arm 2 — Gemini 2.5 Flash zero-shot, both label levels, on the same 100-image held-out test set Arm 1 was scored on. API-only, no A100 needed. This is what turns "three arms" from a promise into something structurally visible, which is the project's whole stated novelty.
  2. Grad-CAM on Arm 1 — checkpoints already exist; this is a few hours of hook-wiring on a frozen CNN, not a research problem. Gives explainability a real, visual, partial deliverable instead of a "not started" line.
  3. Literature review comparison matrix — the 15-paper review, research-gap, and novelty sections already exist in GROUP 14 LITERATURE REVIEW FL.pdf. The rubric wants an explicit 4–5-paper side-by-side matrix (task / language / modality / explainability / fine-tuning / this work) — that's a reformatting pass over material you've already written, not new research.
  4. Finalize the system design artifact — diagrams already exist (System design v5.jpg, Overall_Architecture_Elaborated.png, refined_system_architecture_hld.svg). Pick one canonical version, pair it with the LLD module table from the design review doc, and rehearse defending the tech-stack choices (Swin-Tiny vs. a bigger CNN, MuRIL vs. mBERT, why LoRA/QLoRA, why Gradio) — this is prep time, not build time.
  5. One consolidated evaluation table — SYNAPSE paper (0.4256) vs. your replication (0.3183) vs. Arm 1 (0.3940) vs. Arm 2-Gemini (once run). Thirty minutes once #1 lands.
  6. Slide deck, ≤20 slides, diagrams and tables over paragraphs, speaking time split evenly across all three members.

Explicitly skip — say "planned, next milestone," don't half-build

  1. Arm 3 (PEFT fine-tuning) — needs confirmed A100 access plus hours of per-architecture QLoRA debugging. A broken half-attempt reads worse in a viva than a clean "scoped, blocked on compute confirmation, first run planned for [date]" slide.
  2. Full Arm 2 grid (4 models × 3 prompting strategies × 2 levels) — only run the Gemini zero-shot slice above. State the rest as scoped-but-not-yet-run rather than attempting all 12+ configurations in 3 days.
  3. Cross-lingual transfer — hard blocked on the secondary dataset. Don't spend review time here at all.
  4. Hateful Memes reference pass — gated dataset, not acquired. Same treatment.
  5. Demo app — only attempt a stub if #1–#4 land with a full day to spare. Otherwise one slide describing the planned UI (dropdown model choice, Grad-CAM overlay, confidence) is sufficient — it's specified in enough detail already to describe convincingly without building it.
